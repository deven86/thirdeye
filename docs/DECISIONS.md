# Decision log

Each entry: date · decision · why · cost/risk.

## M1 — Foundation (2026-11-04)

1. **Xcode project is generated by XcodeGen from `ios/project.yml`.** The `.xcodeproj` is not committed. Why: project files are hand-unfriendly, merge-conflict-prone, and this repo is authored outside Xcode. Cost: one `brew install xcodegen` + `xcodegen generate` before opening in Xcode (CI does it automatically).
2. **Deployment target iOS/iPadOS 26.0, Swift 6, default MainActor isolation.** Both devices are personal; iOS 26 unlocks Liquid Glass APIs without availability checks. Default MainActor isolation (Xcode 26 "approachable concurrency") keeps UI code simple; network calls are `async` and suspend rather than block.
3. **AI keys are stored in the Keychain as synchronizable generic-password items (`kSecAttrAccessibleWhenUnlocked`).** They sync iPhone ↔ iPad through end-to-end-encrypted iCloud Keychain. Never in UserDefaults, SwiftData or CloudKit. Trade-off: synchronizable items cannot use `…ThisDeviceOnly` classes; revealing a key requires a fresh Face ID check inside the app.
4. **Non-secret settings (theme, tier→model mapping, lock timeout) live in UserDefaults for M1.** They move to SwiftData + CloudKit in M2 when the iCloud container is created; keeping CloudKit out of M1 avoids signing/entitlement friction on the first TestFlight build.
5. **Model lists are fetched live from each provider; nothing is hard-coded.** Tier suggestions (Fast/Balanced/Deep) are heuristics on the model ID that the user can override.
6. **CI/CD copies VISION's proven pipeline.** `macos-15-intel` runner with Xcode 26; fastlane match stores the encrypted certificate/profile on this repo's `match-signing` branch; the match password is derived from the ASC key secret, so only 4 secrets are needed; TestFlight upload is manual (type `UPLOAD`). Build-and-test runs only by hand or on PRs because private-repo macOS minutes are limited and shared with VISION. Bundle ID `com.jondhale.thirdeye` follows VISION's naming.
7. **App lock uses `.deviceOwnerAuthentication`** (Face ID with passcode fallback), re-locks after 30 s in the background, and shows a privacy cover whenever the scene is not active.
8. **Name: Third Eye** (working name in the spec was SCORE1000). Display name "Third Eye", bundle ID `com.jondhale.thirdeye`, repo `deven86/thirdeye`, Xcode target `ThirdEye`. The score itself is still out of 1000.

## M2 — Markets, phone-first (2026-11-04)

9. **Phone-first: no backend until Milestone 6.** Data, charts and (later) AI analysis run on the iPhone. Only background monitoring and alerts need an always-on machine; that arrives in M6 (user's computer or a free cloud function).
10. **Data sources:** Upstox (India: NSE, BSE, F&O, MCX, currency derivatives) with on-device OAuth — the redirect `https://127.0.0.1/thirdeye` is intercepted in a non-persistent WKWebView, the code is exchanged on device, the token stays in this device's Keychain and expires ~03:30 IST next day. Twelve Data (US stocks/ETFs, forex, metals; key in synced Keychain). Binance public market data via `data-api.binance.vision` (no key).
11. **Instrument lists** are downloaded on device (Upstox daily ≈3 MB gz; others weekly), cached LZFSE-compressed in Application Support with complete file protection, excluded from backup. Debt instruments are excluded. Formats were verified against the live files with the Linux `Data probe` workflow.
12. **Charts:** TradingView Lightweight Charts v5.2.1 bundled locally (no CDN), Apache-2.0, attribution logo kept and credited in Disclaimers. Times shifted to IST for Indian instruments.
13. **Live refresh while a chart is visible:** 10 s (1m) to 10 min (1W/1M), stopped when the app leaves the foreground. Upstox WebSocket streaming is deferred; polling stays well inside rate limits.
14. **Watchlist is local** in M2; it moves to iCloud sync with SwiftData later.

## M3 — Feature engine (2026-11-04)

15. **All indicators are computed on device in code** (`Core/Features`). The AI (M4) receives a compact feature pack keyed by stable IDs such as `D.RSI14` and must cite them; it never reads raw candles.
16. **Indicators are verified against TA-Lib 0.8.3**, the industry reference, on a deterministic 300-bar series (golden tests in `FeatureEngineTests`): SMA, EMA, RSI, ATR, MACD, Bollinger, ADX/±DI match to ~1e-13. ATR, MACD and ADX use TA-Lib/Wilder seeding so values match from the first bar.
17. **Patterns report their own track record** on the product being viewed (hit rate after 5 bars, sample size). A pattern only counts as a signal with ≥ 8 past occurrences and ≥ 55 % hit rate.
18. **The "Technicals" lean (Bullish/Mixed/Bearish) is a code-computed count of signals**, clearly labelled as not the AI score.
19. Fixed a chart bug from M2: a theme change could re-trigger the chart's "ready" message in a loop. The chart now reloads data explicitly after theme/locale changes.

## M4 — 10-stage AI analysis (2026-11-04)

20. **Claude is the primary provider.** Stages that need fresh information use Claude's server-side web search (`web_search_20250305`, $10/1,000 searches, max 2–3 per stage). Stages without search use structured outputs (`output_config.format`, JSON Schema without min/max — ranges are enforced in code). The two cannot be combined because web-search citations are always on.
21. **OpenAI and Gemini run in JSON mode without web search.** If a search stage is mapped to them, the stage runs on model knowledge only, is labelled as such, and its confidence is capped at 0.4.
22. **Nothing from the model is trusted unvalidated** (`StageParser`): scores clamped to 1–100, confidence to 0–1, direction derived from the score, sources kept only if the URL was actually retrieved in that call, reasons kept only if they cite a real feature ID or a kept source. No surviving reason → confidence ≤ 0.15. Invalid JSON → one retry → stage marked unavailable (score 50, confidence 0).
23. **The 0–1000 number, vetoes and the take-profit ladder are computed in code.** Stage 10 only proposes side, entry zone, stop and holding days; code validates them (stop side, ≤ 3 ATR from price, risk ¼–4 ATR) and builds TP1–TP5 at 1R–4R + runner. A Fast-tier verifier (separate call) checks the plan against computed facts; its issues block the trade.
24. **Vetoes force "No trade":** fewer than 7 stages, stale data, a major event inside the holding window, any plan issue, or a plan side that contradicts the score.
25. **Stages 1–9 run two at a time** with retry/backoff on 429/529 to stay inside new-account rate limits; the system prompt is prompt-cached.
26. **Every run is saved** (Application Support/analyses, complete file protection) with raw model output, model IDs, prompt version and cost — the audit trail and the future calibration data. Extended thinking is not used yet.
27. **First live run (0.4.1) lessons:** 7 of 10 stages failed JSON parsing and the run cost $1.50 (estimate was ~$0.35). Causes: output limits of 1.2–1.5k tokens cut answers off, and each failure re-ran the full web search. Fixes in 0.4.2: output limits 3–6k (only used tokens are billed); a string-aware JSON scanner that picks the last complete object containing "score"; failures go to a cheap **repair** call (Fast model, guaranteed-shape JSON, no search, instructed not to add facts) instead of a full retry; searches cut to 2 per stage (1 for stage 10) and stage 4 now uses the computed history without search; cost estimate now assumes ~12k tokens per search; every stage shows "Show raw AI output" and flags answers cut off at the length limit.

## M5 — Trades, positions, journal (2026-11-04)

28. **Event veto narrowed:** only product-specific events (results, dividends/splits, index changes, lock-ins, token unlocks) inside the holding window block a trade. Market-wide data (jobs, inflation, central banks) is shown as a non-blocking caution — otherwise every swing trade would be vetoed.
29. **Trades:** upcoming → open → closed/cancelled, with entry and exit fills, fees, take-profit stages, stop moves (TP1 auto-moves the stop to breakeven, only ever tightening). All P&L maths live in `TradeMath` and are unit-tested against hand calculations. P&L is kept per currency — never converted (no invented FX rates).
30. **Position size** = capital × risk % ÷ |entry − stop|, rounded down to the lot size (6 decimals for crypto). Risk per trade capped at 2 % in Settings.
31. **Paper by default;** switching to real money needs Face ID. Each trade is stamped paper/real; journal stats are separate.
32. **Sync:** trades are stored locally (complete file protection) and mirrored to iCloud key-value storage, one key per trade, newest `updatedAt` wins, deletions via tombstones. Chosen over CloudKit/SwiftData because it needs no container, schema or CloudKit console. Limit: ~1 MB total (hundreds of trades); analyses (large) stay on the device. The App ID capabilities (iCloud, Data Protection) must be ticked manually — Apple rejects capability changes made with an App Store Connect API key ("Unauthenticated").
33. **Live prices** for trades use single-quote endpoints (Binance ticker, Twelve Data /price, Upstox v3 LTP with candle fallback — Upstox shape not yet verified live), refreshed every 30 s only while visible. Foreground hints only; background alerts are M6.

## Portfolio (2026-11-04)

34. **Portfolio tab** (paper / real): per-currency current value, open cost, unrealised, realised this month and all time, and **open risk** (what you lose if every current stop is hit; 0 once a stop protects the entry), with a warning above 6 % of capital. Allocation donut by product / type / market, realised equity curve, open positions. An approximate single ₹ total appears only when a live USD/INR rate is available, and shows the rate and time used; USDT counts as USD. No rate → no total (never guessed). Maths in `PortfolioMath`, unit-tested.

## M7 — Hot trades (2026-11-04)

35. **Three-step scan, run only on demand with a cost confirmation:** (1) code screens a market's list on daily technicals — free; (2) a Fast model shortlists 3 of the top 15 (falls back to the code ranking); (3) each gets the full 10-stage analysis, one at a time. ≈ 3 × analysis cost + ~$0.01.
36. **Only picks whose full analysis ends in Buy/Sell are labelled HOT.** If none pass, the app says "No hot trades right now" instead of forcing picks.
37. **Universes:** crypto = top 30 USDT pairs by 24 h volume (stablecoins and leveraged tokens excluded); US = 30 large caps; forex & metals = 12 pairs incl. XAU/USD, USD/INR; India = ~50 large NSE names (curated, not an official index; unmatched symbols skipped). Indian cash shares are long-only in swing scans (no overnight shorting). Twelve Data scans are paced at 8 requests/minute for the free plan.

## Scoring v2 and Hot trades v2 (0.8.0, 2026-11-04)

38. **The version-1 score was squeezed toward 500, so Buy/Sell was almost unreachable.** Three layers of hedging stacked up: the prompt told models to "use the full range only for overwhelming evidence"; the formula then pulled each score toward 50 by its confidence (effective = 50 + c × (s − 50), with typical c = 0.4–0.6); and failed stages counted as 50 at full weight. On the swing weights: every stage at 70 → 600 (No trade); a clear bullish set (technicals 70–74, context 55–62) → 610; **every stage clearly bearish → 391 (No trade)**. Version 2: **C = 10 × Σ(w·c·s) / Σ(w·c) over completed stages** — confidence decides how much a stage counts, not how far it is dragged to neutral; failed stages are left out. Same examples: 700, 680 (Buy), 322 (Sell). Bands unchanged (≥ 750 / 620 / 381–619 / 380 / ≤ 250).
39. **Discipline moved from the number into explicit checks**, all shown on the report with ✓/✗: score in a trade band; ≥ 7 stages; **evidence** Σ(w·c)/Σw ≥ 35 %; **agreement** ≥ 50 % of the stage weight on the trade's side and ≤ 30 % against (stops one loud stage carrying a verdict — e.g. stage 10 at 90 with the rest neutral gives 624 but fails); fresh data; no product event inside the holding window; **a plan that exists and agrees** (0.7 could show "Buy" with no entry/stop); Indian cash shares can't be held short overnight (read as "avoid / exit"). Grade A+/A/B from conviction, evidence and agreement. No-trade results that lean (≥ 580 or ≤ 430) are **Watch**, with the nearest support/resistance to watch.
40. **Measured "edge" was tested and rejected as a gate.** Prototype: replay the exact plan (1.5-ATR stop, 1R–4R ladder, 15 days) from every past day in the same state (trend × RSI) and shrink toward the product's baseline. Walk-forward on 28 coins (Binance daily, Feb 2024–Nov 2026, 7,874 out-of-sample cases, edge computed only from earlier data): Spearman −0.04 between predicted and realised R; the highest-edge bucket (> +0.3R) realised −0.24R. Simple chart rules (trend state, RSI zone, distance to levels) showed no stable edge in the same window — results were dominated by the 2025–26 regime change. So history never changes a verdict. What is kept: a **history check** of the plan (stop-first rate, TP1/TP2 rates, average R after costs, worst losing streak) to size positions realistically, labelled "not a forecast". Scripts: research-data workflow + `scratchpad/research/*.py` (prototype mirrored by `PlanReplay`, golden values in tests).
41. **Prompts p4:** anchored score scale (60/40 slight, 70/30 clear lean = typical tradable setup, 80/20 strong, 90+/10− rare); "do not pull the score toward 50 because you are unsure — put doubt in confidence"; confidence anchors 0.2/0.5/0.7/0.9. Stage 10 must propose a plan when its score is ≥ 60 or ≤ 40 and a sound entry/stop exists (entry within ~1 ATR, stop 1–2.5 ATR beyond a level), and is told when shorts are impossible.
42. **Hot-trades universe hygiene:** Binance's top volume list now includes tokenised US shares (SOXLB = a 3× leveraged chip ETF, NVDAB, TSLAB…, all listed June–July 2026), new stablecoins (U, RWUSD, USD1) and gold tokens (XAUT). Crypto scans now require ≥ 400 daily bars (keeps out new listings and tokenised shares), drop pegged coins by behaviour (daily σ < 0.1 %) as well as by name, and fill to 30 eligible coins from the top 45. Skips are listed with reasons.
43. **Shortlist robustness:** 0.7's three picks all read "Top technical score", i.e. the AI shortlist silently fell back. Now the schema restricts `symbol` to the exact list (`enum`), symbols are matched leniently (PEPE / PEPEUSDT / PEPE/USDT), short AI lists are topped up from the chart ranking, and any fallback is stated on the results. The shortlist also sees market breadth (share above the 50-day average), BTC's trend and each name's 20-day relative strength vs the list median. Scans can analyse the top 3 or top 5. Results are ranked HOT (by grade) → WATCH → WAIT, each with its blocking reason.
44. **Independent review of v2 (separate agent, no shared context) — fixes:** stages with zero weight (scalp stages 3–4) count as completed; for positional / long-term / equal holds only a product event in the next 14 days blocks (a results date inside a 4-month hold is normal and becomes "expect a possible gap"); swing/scalp still block events inside the plan's own holding days; an unanswered event question is a non-blocking "check yourself", not "none found" (the parser records whether stage 2 answered); scores within 30 of 500 are "balanced", never "down"; the "can't hold short" check runs only when the number is in a Sell band; grades are symmetric around 500 (bands 620/380, 750/250); watch levels for products that can't be shorted show only long-side levels; Hot-trades India scans allow shorts on Scalp/Intraday; intraday session hours per market (crypto/FX/metals 24 h, US 6.5 h, NSE/BSE 6.25 h, MCX 14 h).
45. **CI runner choice:** both Mac workflows take a `runner` input (`macos-15-intel` default, `macos-26` Apple silicon), each with its own concurrency group. On 2026-11-04 hosted Mac jobs were intermittently never assigned a runner and auto-cancelled after 15 minutes (actions/runner#4833); the release script retries on both runner types.

## M6 — Alerts from the Windows PC (0.9.0, 2026-11-05)

46. **Architecture (user's choices: native notifications + Tailscale):** a small Go service on the user's always-on Windows PC watches every upcoming/open trade and sends Apple push notifications itself (token-based APNs key, ES256 JWT). The app talks to it over **Tailscale** (`tailscale serve` → HTTPS on the PC's MagicDNS name, tailnet-only); the service listens on 127.0.0.1 only. Chosen over Telegram (would leave the app) and iCloud Drive file sync (slower, needs another iCloud container). The service is standard-library Go so it builds and tests on Linux CI (no Mac runner) and cross-compiles to a single `thirdeye-monitor.exe`; released as `monitor-v*` on GitHub.
47. **What it watches and when:** cadence from the trade's holding badge (30 s scalp/intraday, 5 min short-term/swing, 30 min positional, 1 h long-term), 1 min when an open trade is within ½R of its stop; only during market hours (crypto 24/7; FX & metals Sun 17:00–Fri 17:00 New York; US 09:30–16:00 New York; NSE/BSE 09:15–15:30 IST; MCX 09:00–23:55; currency F&O 09:00–17:00; holidays not modelled). Twelve Data is budgeted at 8 symbols a minute (free plan). Upstox uses the user's daily token, passed from the app and treated as expired after 03:30 IST.
48. **Alert rules** (each fires once; plan changes re-arm the stop/entry ones): entry zone (re-arms after leaving by ½R), invalidated before entry, stop hit, near stop ≤ 0.25R (re-arms at ≥ ½R), each unbooked take-profit with its instruction, time limit / plan expired, sharp adverse move ≥ 1R from the last hour's best price (2 h cooldown), gap ≥ 0.75R after ≥ 6 h without a price, 09:00/21:00 digest (within 30 min of the time), Upstox-login reminder once per weekday morning. Stop, near-stop, sharp-move and gap alerts are **time-sensitive** (break through Focus). Alert history (200) is kept and shown in the app.
49. **Security:** one-time 6-digit pairing code (15 min, 10 tries) → 256-bit bearer token (only its hash stored on the PC; device-only keychain on the iPhone); admin endpoints need a local key and refuse requests that came through the Tailscale proxy; the APNs key, Twelve Data key and Upstox token are DPAPI-encrypted on the PC; the `.p8` file is imported automatically from the program folder and renamed. The monitor only reads prices — it never trades.
50. **Running 24×7 on Windows:** a Task Scheduler task as SYSTEM, at boot and every 5 minutes (a second copy exits because the port is taken — a self-healing watchdog after crashes, updates and power cuts), no 3-day time limit, `SetThreadExecutionState` keeps the PC from sleeping. The app shows "PC monitor offline" when the last price check is older than 15 minutes. Apple capabilities **Push Notifications** and **Time Sensitive Notifications** must be ticked by hand on the App ID (the API key can't), then signing is refreshed.

## Next builds in 0.9.0 (2026-11-05)

51. **Report card (calibration data):** every finished analysis is graded on the device once its holding period has passed (plan's days; without a plan 1/10/60/180/30 days by profile) from daily candles that start after the analysis: forward return, whether the price went the way the score pointed (no call when the v2 score is within 30 of 500), best/worst move, and — for runs with a plan — whether the entry zone was reached and the plan's result in R, managed with the real stop and take-profit prices (fill at the zone's middle, management from the next bar, stop before targets). The card shows Buy/Sell plans as if followed (win %, average R), direction accuracy by score band, score↔return correlation, and each stage's direction hit-rate. It warns that < 30 results prove nothing. Re-weighting stages (the calibration step) waits for ~50 results per stage. Grading runs on launch, at most every 30 min, 12 runs per pass, one candle download per product, ≤ 6 Twelve Data calls.
52. **Cheaper repeat analyses:** stages 1–4, 7, 8 (news, events, leadership, long-term history, sector, connected products) are reused from the newest analysis of the same product and holding profile within 12 h (setting: Off/6/12/24 h), same prompt version only, never chained, with event countdowns reduced by the days passed and the stage marked "Reused … no new AI cost". The technical stages (5, 6, 9) and the final stage always run fresh.
53. **Risk guard** (advice before saving a trade; Settings → Trading & risk guard): realised R of the last 7 days in the current mode — at or below −3R (setting 1–10R) the guard says pause and saving needs "I understand — save anyway", and Home shows a banner; total open risk after the new trade vs a cap (default 6 % of that currency's capital); same bet — open/upcoming trades in the same direction whose 60-day daily returns correlate ≥ 0.7 with the new product (measured for up to 5 products), or any two crypto trades when correlation can't be measured.
